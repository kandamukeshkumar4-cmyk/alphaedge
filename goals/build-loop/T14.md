## Design (first-principles)

What must be true:
- Reuse, don't rebuild: format the T10 daily digest summary into a phone-readable
  message and push it through the T09 AlertDispatchService (which already does
  Telegram + webhook with failure isolation = the "multi-provider fallback").
- OFF by default (`digest_distribution_enabled=False`) — no external calls when off.
- Dedupe per day: pass a date-keyed dedupe_key; AlertDispatchService's process-level
  dedupe gives per-day suppression for free.
- No new external plumbing, no order path, no TA strategy.

Derived approach:
- `services/digest_distribution.py`: `DigestDistributionService(session, settings,
  transport)`:
  - `format_digest(summary, *, date_str) -> str` — compact, phone-readable.
  - `distribute(summary, *, now) -> bool` — off → return False (no calls); else
    dispatch via AlertDispatchService(alert_type="digest", dedupe_key=
    f"digest-dist:{date}"). Returns True if dispatched, False if off/deduped.
- config: `digest_distribution_enabled` (default False).
- Wire: end of `morning_research_task` — if enabled and run_daily wasn't skipped,
  distribute(summary). Failure-isolated.
- Tests: format shape; disabled → no Alert row + False; enabled → Alert row
  (alert_type=digest) + per-day dedupe (2nd call False); skipped-summary → no-op.

Guardrail: text formatting + push only; reuses guardrailed alert channels; no order
path; no TA. PASS. No schema change.

=== THE VERIFIED BUG ===
GET /api/v1/markets returns the ENTIRE catalog on every call: 2,353,865 bytes, ~1.3s.
Measured in prod, three ways — the size is byte-identical regardless of query params:
    /api/v1/markets                 -> 2353865 bytes
    /api/v1/markets?limit=3         -> 2353865 bytes
    /api/v1/markets?limit=5&offset=0-> 2353865 bytes
Root cause (already diagnosed, confirm it then fix it): backend/app/api/v1/routes.py L89-107,
`async def list_markets(category, sort, q, db)` has NO limit/offset parameters at all. FastAPI
silently discards the unknown query args, so the frontend "asking for 3" is a no-op. Every first
paint of Discover, /markets and /trade downloads the whole catalog.

=== DESIGN DECISIONS (made for you — implement exactly) ===
1. KEEP the response shape `list[MarketResponse]`. Do NOT introduce an envelope object
   ({items, total}) — that would break every existing consumer. Pagination metadata travels in
   RESPONSE HEADERS instead.
2. Add `limit: int = 100` and `offset: int = 0` to list_markets.
   Validation: 1 <= limit <= 500, offset >= 0, else HTTP 400 (match the existing style at
   routes.py L98-101 and the /search handler L120-123).
3. Set response headers on every 200: `X-Total-Count` (total matching BEFORE slicing) and
   `X-Page-Limit`, `X-Page-Offset`. Use a `Response` parameter injected by FastAPI.
4. Slice in the SERVICE, not the router: add limit/offset to
   `MarketService.list_public_markets` so the DB does the work (LIMIT/OFFSET in the query), and
   return the total count alongside. Do not fetch-all-then-slice-in-Python — that keeps the cost.
   New signature:
     async def list_public_markets(self, *, category=None, sort="volume", q=None,
                                   limit: int = 100, offset: int = 0) -> tuple[list, int]
   (returns (rows, total_count))
5. CACHE: the existing `markets_cache` key at routes.py L101 is `(category, sort, q)` and now
   under-keys the result. Change the key to `(category, sort, q, limit, offset)` and cache the
   `(rows, total)` tuple. Missing this is a correctness bug — a cached page-1 would be served for
   page-2 requests.
6. DEFAULT CHANGE IS INTENTIONAL AND BREAKING: callers that previously got everything now get 100.
   That is the point. A separate frontend node updates the consumers against the contract below.

--- FROZEN CONTRACT (a frontend node builds against this in parallel — do not deviate) ---
GET /api/v1/markets?category=&sort=volume&q=&limit=100&offset=0
  200 -> list[MarketResponse]  (UNCHANGED item shape)
  headers: X-Total-Count: <int>, X-Page-Limit: <int>, X-Page-Offset: <int>
  400 -> limit outside 1..500, or offset < 0, or existing invalid category/sort
